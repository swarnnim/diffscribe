# DiffScribe

DiffScribe reads a git diff and drafts the two texts every change needs
and nobody enjoys writing: a **conventional-commit message** and a
**changelog entry**. It runs entirely on your machine — an open-weight
language model (Qwen2.5-0.5B-Instruct, Apache 2.0) served locally by
llama.cpp (MIT), wrapped in deterministic guardrails. No API keys, no
accounts, no network after a one-time download, nothing to paste into a
web AI.

The design rule is strict: **the model words things; code counts
things.** Every file count and +/- number in the output is computed by
parsing the diff — the model never writes a number. The model's two
texts are validated before use, and anything that fails validation is
replaced by a labeled, deterministic rule-based draft.

Built for the DEV Hacktoberfest 2026 Week 4 challenge ("Build something
with open-source AI at its core").

## Quick start

```bash
# 1. One-time downloads (the only step that needs the network)
./scripts/download-llamacpp.sh   # llama.cpp binary, MIT
./scripts/download-model.sh      # Qwen2.5-0.5B-Instruct GGUF, Apache 2.0

# 2. Draft from your staged changes
git add -A
python3 -m diffscribe draft

# or from a saved diff, or stdin
python3 -m diffscribe draft --diff some-change.diff
git diff HEAD~1 | python3 -m diffscribe draft --stdin

# 3. Run the recorded demo (regenerates demo-output.txt)
./scripts/demo.sh
```

Requirements: Python 3.8+ (standard library only — no pip installs),
git, curl, tar. About 540 MB of disk for the model and engine.

## Example

Real output from `./scripts/demo.sh`, drafting for
`sample_diff/feature.diff` — a genuine staged diff (a README usage
section, a new test file, and a new `count_sentences` function in a toy
text-statistics project; regenerate it with
`scripts/make-sample-diff.sh`):

```
=== DIFFSCRIBE draft ===
method: local open-weight model Qwen2.5-0.5B-Instruct (Q4_K_M, Apache 2.0) via llama.cpp (greedy decoding); both texts parsed and validated, stats counted deterministically

COMMIT MESSAGE:
feat: add docstring for textstat/count.py

Files changed: 3 (+20 -1)
- README.md: +5 -1 (modified)
- tests/test_count.py: +9 -0 (added)
- textstat/count.py: +6 -0 (modified)

CHANGELOG ENTRY (Unreleased):
- Updated README for easy navigation
- Added new installation steps
- Updated tests with new code
- Improved textstat count functionality

Every number above was counted from the diff by code. The model only worded the texts marked as its own.
```

Read it critically, because DiffScribe's whole point is that you can:
the subject is well-formed and on-topic, but the diff adds a *function*,
not a docstring; and the README gained a usage section, not
"installation steps". A 0.5B model is a drafter, not an oracle — you
edit before you commit. What it cannot do is invent the numbers or
produce a malformed subject: those are checked by code.

With `--no-llm`, the same diff gets the fully deterministic draft
(exact stats, no model wording at all) — see `demo-output.txt` for both
runs, recorded verbatim.

## How it works

1. **Parse** (`diffscribe/digest.py`) — the unified diff is parsed into
   per-file changes: path, kind (added / modified / deleted / renamed),
   binary flag, exact added/deleted line counts, and a few "signal"
   lines (added lines that open a definition, like `def` / `class` /
   `function`), which hint at what the change does.
2. **Digest** — the parsed changes are rendered into a compact text
   digest (capped at 1,400 characters; per-file entries truncate
   before whole files are dropped, and the exact totals line is always
   present).
3. **Draft** (`diffscribe/llm.py`) — the local model is asked for the
   two wordings in two separate calls, each with a one-shot format
   example: a conventional-commit subject, then 1–6 changelog bullets.
   Greedy decoding (temperature 0) keeps runs reproducible.
4. **Validate** (`diffscribe/draft.py`) — deterministic checks, per
   text, independently:
   - the subject must match the conventional-commit shape, be a single
     line of at most 100 characters, and carry no trailing period;
   - its scope, if any, must be **grounded**: it has to appear in a
     changed file's path or signal lines. (During development the model
     parroted the one-shot example and produced `feat(auth): reject
     expired tokens during login` for a diff containing no auth code.
     This check exists because of that run.)
   - bullets must be 1–6 lines of at most 140 characters each.
   Anything that fails is replaced by a rule-based draft (type inferred
   from the change shape, exact stats included) and the output says so.
5. **Assemble** — the commit body (per-file stats) is generated by code
   alone; model and fallback texts are labeled in the output.

## Project layout

```
diffscribe/
  __main__.py   CLI: draft --diff FILE | --stdin | staged; --no-llm
  digest.py     diff parsing, digest building, rule-based drafting
  draft.py      output validation, scope grounding, assembly, rendering
  llm.py        llama.cpp wrapper and prompts
sample_diff/
  feature.diff  a real staged diff, used by the demo
scripts/
  download-llamacpp.sh   one-time llama.cpp download (verified fetch)
  download-model.sh      one-time model download
  make-sample-diff.sh    regenerates sample_diff/feature.diff
  demo.sh                records demo-output.txt
tests/          50 unit tests (python3 -m unittest discover -s tests)
demo-output.txt recorded demo transcript (both modes)
```

## Tests

```bash
python3 -m unittest discover -s tests
# Ran 50 tests — OK
```

The suite covers diff parsing (including header-like content lines and
binary/rename entries), digest truncation, subject and bullet
validation, scope grounding, fallback drafting with exact expected
strings, and end-to-end rendering.

## Honest limitations

- **The model is tiny (0.5B) and it shows.** Subjects are usually
  well-formed but can mischaracterize a change (see the example above);
  bullets can contain plausible details the diff doesn't quite support.
  DiffScribe validates *shape and grounding*, not truth. Always read
  the draft before committing.
- **Scope grounding is a substring heuristic.** It catches wholesale
  example leakage, not subtle irrelevance (a scope of `auth` would also
  match a path containing `author`).
- **Huge diffs are digested, not read.** Beyond the digest cap, the
  model sees early files in full and later ones summarized; the stats
  body still covers every file exactly.
- **Rename detection is shallow** — it trusts the diff's own
  `rename from/to` headers; content changes inside a renamed file are
  counted, but similarity percentages are ignored.
- **Conventional-commit types are inferred coarsely** in fallback mode
  (docs / test / feat / chore). The model usually does better; the
  fallback prefers being vague over being wrong.
- **No partner/hosted technology is used** — deliberately. Everything
  is local and offline, which is the point of the project.
