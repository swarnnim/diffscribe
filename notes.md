## What was built

**DiffScribe** — a local CLI that drafts a conventional-commit message
and a changelog entry from a git diff.

- `diffscribe/digest.py` — unified-diff parser (per-file kind, exact
  +/- counts, binary/rename handling, ≤3 "signal" definition lines per
  file), a capped digest builder (1,400 chars; per-entry truncation
  before whole-file drops; exact totals always present), and the
  rule-based fallback drafter (type inferred docs/test/feat/chore,
  scope = single common top-level directory).
- `diffscribe/llm.py` — llama-cli wrapper (Week 3 pattern): chat-ml
  prompts, `SUBJECT:`/`BULLETS:` anchors, greedy decoding; two separate
  one-shot calls. Examples are deliberately bland (a README edit) after
  the leakage incident below.
- `diffscribe/draft.py` — validators (conventional-commit shape, single
  line, ≤100 chars, no trailing period; bullets 1–6 × ≤140 chars),
  **scope grounding check** (a scoped subject's scope must appear in a
  changed path or signal line), independent per-text fallbacks with
  labels, render.
- `diffscribe/__main__.py` — CLI: `draft --diff FILE | --stdin |
  (default: git diff --staged)`, `--no-llm`, model/engine overrides.
- `sample_diff/feature.diff` — a REAL staged diff generated by
  `scripts/make-sample-diff.sh` (scratch repo "textstat": README usage
  section +5−1, new tests/test_count.py +9, count_sentences added to
  textstat/count.py +6; totals 3 files, +20 −1).
- Scripts: download-llamacpp.sh (fixed + hardened, see failures),
  download-model.sh, make-sample-diff.sh, demo.sh.
- LICENSE: MIT, "Copyright (c) 2026 Swarnnim Agnihotri" (same as wk3).

## Engineering decisions (inherited pattern, Week 2/3)

- Per-text small model outputs + deterministic validation + **labeled**
  rule-based fallback per text, independently — a bad subject never
  sinks good bullets and vice versa.
- **The model never writes a number.** The stats body is generated by
  code from the parsed diff; model texts are wording only.
- Greedy decoding (temp 0): the recorded demo reproduces — the
  pre-demo smoke run and the demo run produced byte-identical model
  output.
- Stdlib-only Python; llama.cpp binary + GGUF fetched by scripts and
  gitignored; repo ships code + sample diff + transcripts only.

## What failed during development (kept honest, per the playbook)

1. **Example leakage (the big one).** First model smoke run, with an
   auth-flavored one-shot example, returned the subject
   `feat(auth): reject expired tokens during login` — near-verbatim
   example text — for the textstat diff, which contains no auth code.
   All format checks passed. Fixes: (a) examples replaced with a bland,
   topically distant README-edit example; (b) deterministic **scope
   grounding check** added; (c) regression test
   `test_assemble_rejects_leaked_example_subject`. After the fix the
   model produced an on-topic subject for the same diff.
2. **Copied download script had a latent URL typo.** Week 3's
   download-llamacpp.sh builds the asset name as `llama-b${VER}` with
   VER=b11580 → `llama-bb11580-bin-ubuntu-x64.tar.gz` → GitHub 404
   ("Not Found" body saved as the tarball). It failed repeatedly and was
   initially misdiagnosed as egress-proxy flakiness (a hand-typed
   correct URL succeeded once mid-window, feeding the wrong theory);
   a `bash -x` trace exposed the doubled "b". Fixed to `llama-${VER}`
   and hardened: download to temp file, verify with `tar tzf`, retry
   up to 5 times. NOTE: Week 3's published repo carries the same typo —
   its binary was evidently fetched another way in that session. Out of
   scope here; flagging for a future fix commit to the SlothPlan repo.
3. **Misleading fallback labels in --no-llm mode.** The renderer
   initially printed "(subject drafted by the deterministic fallback —
   the model's subject could not be validated)" even when no model had
   run at all. Fixed: per-text labels suppressed in --no-llm mode (the
   method note explains it), and label wording changed to "could not be
   used" (accurate for both invalid output and model-unavailable).
   Covered by `test_render_labels_can_be_suppressed`.
4. **Model near-misses shipped as-is in the demo.** The recorded
   subject says "add docstring" where the diff adds a function; one
   bullet says "installation steps" where the README adds usage docs.
   Not edited, not re-rolled — presented in the post/README with an
   explicit skeptical reading. This is the honest capability level of
   a 0.5B local model under shape+grounding validation.
